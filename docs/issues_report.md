## 0. システム概要

```
[車載カメラ/バス] → (リアルタイム登録) → SQLite: pointed_road_data（他システムと共有）
                                              │
     cron 5分毎: generate_cache.py ───────────┤ 直近24hを抽出・クレンジング
                                              ▼
 geojson/(国土数値情報 N13 道路) ──► 最寄り道路へ空間結合(50m以内) ──► cache/recent_matched.pkl
                                              │                         （紐付け済み観測）
                                              ▼
  Flask app.py ── /api/roads/geometry   道路形状（gzip・長期キャッシュ）
              ├── /api/roads/status     指定範囲で代表点を選出（現在/過去）
              ├── /api/roads/<id>/timeline  区間の観測推移
              └── /healthz              キャッシュ鮮度の監視
                                              │
                Apache (/WinterRoad-Overview-LineStyle) リバースプロキシ
                                              │
  ブラウザ: Leaflet(Canvas) + 地理院淡色地図 + noUiSlider（ES Modules）
```

### 0.1 WIPS について

WIPS（Weighted Intensity of Power Spectra）は、Hagiwara et al.（2006）が CCTV のデジタル画像から**視程不良を判定するために提案した指標**です。画像を空間周波数に分解すると、視界が良い場面では遠景の輪郭や模様などの細かい成分（高い周波数成分）が多く含まれます。一方、吹雪や霧で視程が悪化すると、それらがぼやけて失われます。WIPS はこの周波数成分の強さ（パワースペクトル）を重み付けして集計し、**値が小さいほど視程が悪い**ことを表します。

本システムの WIPS は、車載カメラ側の処理（`calWIPSfromJPG/test1.py`）で次のように算出されています。

1. グレースケール画像の中央 256×256 画素を切り出し、2次元 FFT を行う
2. パワースペクトル（振幅の2乗）のうち、直流付近（中心 ±19 画素）を除いた中心 ±32 画素の範囲を合計する
3. その対数をとる（`log(Σ power)`）
4. 10フレームのうち**最小の WIPS** を採用し、その画像で路面状態を判別する

この算出方法から、データの性質として次のことが言えます。

- `-Inf` は**パワーの合計が0**、つまり完全に平坦な画像（真っ黒・真っ白など）で `log(0)` になったものです。視程の情報ではなく、カメラや画像の異常と考えるのが妥当です。
- 負の値はパワーの合計が1未満の、ほぼ平坦な画像です。ホワイトアウトの可能性も、レンズの汚れの可能性もあり、判断にはドメイン知識が必要です。
- 閾値 7.5 / 8.0（画面の色分け）は、この尺度を前提にした値です。

> 論文本文は出版社サイトでアクセスが制限されていたため、算出方法の記述は上記のカメラ側コードに基づいています。論文の評価結果（視程距離との対応関係など）を閾値の根拠として引用する場合は、原文で確認してください。

## 8. 改修で新たに分かったこと・変更点

- **`config.py` の道路分類のコメントが誤っていた**: 国土数値情報 N13 の `N13_003` は「1 国道 / 2 都道府県道 / 3 市区町村道等 / 4 高速自動車国道等」です。抽出対象 `{1, 2, 4}` は「国道・都道府県道・高速」となり、コメント（1=高速, 2=一般国道, 4=主要地方道）とは異なっていました。抽出対象は変えず、コメントと表示名を修正しました。
- **API の変更**: 画面は新しい `/api/roads/geometry`・`/api/roads/status`・`/api/roads/<id>/timeline` を使います。旧 `/api/roads/recent`・`/api/roads/search` は他システムでの利用を確認中のため、**レスポンスの形を変えずに残しています**（`services/legacy_api.py`）。旧実装との違いは次の不具合修正のみです。
  - WIPS の `-Inf` を平均から除外（旧実装では JSON として不正なレスポンスになっていた）
  - `display_route_name` が路線名になった（旧実装は幅員区分の番号）
  - `image_path`・`road_surface` は期間内で最も新しい観測のもの（旧実装は DB への登録順で最後の行で、`last_updated` と別の観測になることがあった）
