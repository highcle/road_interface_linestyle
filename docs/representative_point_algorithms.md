# 区間代表点の選出アルゴリズム 提案書

- 作成日: 2026-11-24
- 対象: 冬季道路情報提供インターフェース（線的表示）プロトタイプ
- 実装: `services/representative.py`（採用方式 B のみ実装）

1つの道路区間に複数の観測点がある場合、地図に表示する値（WIPS・路面状態・観測時刻・画像）をどう決めるかを整理します。候補を複数挙げて比較し、プロトタイプとして採用した方式の根拠を説明します。

---

## 1. 前提

### 1.1 観測データの性質

| 項目 | 内容 |
|---|---|
| 観測の発生源 | 路線バス等の車載カメラ。1台が区間を通過する間に、数秒〜十数秒間隔で複数の観測が記録される |
| WIPS | 画像中央 256×256 画素の2次元 FFT について、直流付近を除いた周波数帯のパワーの総和の対数（`calWIPSfromJPG/test1.py`）。**値が小さいほど画像の細部が失われている＝視程が悪い**（Hagiwara et al., 2006） |
| 上流の処理 | 10フレームの WIPS を計算して**最小値**を採用し、**WIPS 最小の画像で路面状態を判別**している（`calWIPSfromJPG/parameter.py` のコメント「WIPSが最小となる画像に対する路面状態判別」） |
| 区間の粒度 | 国土数値情報 N13 の道路中心線。交差点等で分割され、短いものは数十 m |
| 区間あたりの観測量（テストDB） | 直近24時間: 観測数の中央値 2、2回以上通過された区間 50% / 冬期1週間: 観測数の中央値 6、2回以上通過 76% |

### 1.2 代表点に求められる性質

| # | 性質 | 説明 |
|---|---|---|
| R1 | 鮮度 | 現在の状況を表す。古い観測が新しい観測を上書きしない |
| R2 | 安全側 | 視程不良・路面悪化を見逃しにくい（運転者への注意喚起が目的） |
| R3 | 整合性 | WIPS・路面状態・時刻・画像が同じ観測に由来する（画像で根拠を確かめられる） |
| R4 | 頑健性 | 単発の異常値（遮蔽物、対向車のライト、異常フレーム）に振り回されない |
| R5 | 説明可能性 | 「なぜこの値か」を利用者・管理者に一言で説明できる |
| R6 | 計算コスト | 5分ごとの更新、スライダー操作に耐える |

R1 と R4 は相反し、R2 と R4 も相反します。どれを優先するかが方式選択の本質です。

## 2. 候補アルゴリズム

用語: **通過（pass）** とは、同じ車両が同じ区間で記録した観測のうち、時間間隔が一定（既定10分）以内で連続するまとまりを指します。1回の通過内の観測は、ほぼ同時刻・同条件とみなせます。

### A. 最新観測
- **定義**: 期間内で最も新しい観測1点。
- **長所**: 最も単純で鮮度が最大（R1）。実在する観測なので整合的（R3）。
- **短所**: 1フレームの偶発的な値（ワイパー、対向車、遮蔽）がそのまま出る（R4 弱）。同じ通過の直前の観測が悪くても無視される（R2 弱）。
- **向く用途**: 観測間隔が十分長く、1観測の信頼性が高い場合。

### B. 最新通過内の最小 WIPS 観測（**採用**）
- **定義**: 最新の通過を選び、その中で WIPS が最小の観測を代表点にする（詳細は 4 章）。
- **長所**: 古い通過を使わない（R1）。通過内では悪い側を採る（R2）。実在する観測（R3）。上流が「10フレーム中の最小＋その画像で路面判別」としている考え方と同じ構造で、説明しやすい（R5）。
- **短所**: 通過内の単発的な低い値を拾う（R4 は中程度）。通過が1観測だけの区間では A と同じになる。

### C. 期間内の最小
- **定義**: 表示期間内の全観測の WIPS 最小値（およびその観測）。
- **長所**: 見逃しが最も少ない（R2 最大）。
- **短所**: 期間が長いほど古い悪天候が残り続ける（R1 弱）。テストDBの冬期1週間では、**視程不良の区間が採用方式の約4倍（1,958 vs 480）** になった。

### D. 期間内の平均（旧実装）
- **定義**: 期間内の全観測の WIPS 平均。
- **長所**: ばらつきを平滑化する（R4）。
- **短所**: 一時的な悪化が平均で薄まる（R2 弱）。古い観測も同じ重みで混ざる（R1 弱）。平均値は実在する観測ではないため、路面状態・画像と対応しない（R3 ×）。±Inf が1件あると全体が壊れる。テストDBの冬期1日では、**視程不良が採用方式の約1/4（20 vs 75）** だった。

### E. 期間内の中央値
- **定義**: 期間内の全観測の WIPS 中央値。
- **長所**: 外れ値に最も強い（R4 最大）。
- **短所**: D と同様に一時的な悪化を消しやすく（R2 弱）、新旧を区別しない（R1 弱）。

### F. 期間内の下位パーセンタイル（例: 10%点）
- **定義**: 期間内 WIPS の下位10%点。
- **長所**: C より外れ値に強く、D・E より安全側。
- **短所**: 観測数が少ないと実質 C と同じになる（中央値2観測の区間が多い）。期間が長いと C と同じ問題が出る。

### G. 時間減衰加重平均
- **定義**: 観測ごとに `重み = 0.5^(経過時間 / 半減期)` を掛けた加重平均（例: 半減期60分）。
- **長所**: 鮮度と平滑化を両立できる（R1・R4）。
- **短所**: 平均なので実在する観測ではない（R3 ×）。半減期の設定に根拠が要る（R5 弱）。安全側ではない（R2 弱）。

### H. 最新通過の中央値
- **定義**: 最新の通過内の WIPS 中央値（代表観測は中央値に最も近い観測）。
- **長所**: 鮮度を保ちつつ、通過内の単発値に強い（R1・R4）。
- **短所**: 通過内で一瞬見えた視程不良を落とす（R2 は B より弱い）。

### I. 空間代表（区間中点に最も近い観測）
- **定義**: 最新の通過で、区間の中点に最も近い観測。
- **長所**: 「区間の真ん中の状況」という直感的な説明ができる。
- **短所**: 位置以外の根拠がない。GPS の誤差（数 m〜十数 m）が短い区間では選択を左右する。

### J. 路面状態の多数決・最悪値（路面状態専用）
- **定義**: 路面状態を WIPS と独立に決める。最新通過内の多数決、または滑りやすさ順で最悪の区分を採る。
- **長所**: 路面判別の誤りを多数決で抑えられる。最悪値なら安全側。
- **短所**: WIPS の観測と別の観測になりうる（R3 ×）。区分の順序付け（凍結＞積雪＞シャーベット…）はドメインの合意が必要。

### K. 信頼度重み付き（品質スコア併用）
- **定義**: 画像品質（夜間、逆光、露出、車両ごとの較正状態など）から観測ごとの信頼度を推定し、信頼度の高い観測を優先、または重み付けする。
- **長所**: 本質的な改善になる。車両固有の偏り（後述の `bus_J`・`bus_K`）にも対処できる。
- **短所**: 信頼度モデルの構築と検証が必要で、プロトタイプの範囲を超える。

### L. 状態推定（時系列モデル）
- **定義**: 区間ごとの「真の状態」を隠れ変数とし、観測を逐次取り込んで推定する（カルマンフィルタ、隠れマルコフモデル等）。観測がない時間帯の不確かさも表現できる。
- **長所**: 理論的に最も筋が良い。「◯時間観測がないので不確か」を数値で示せる。
- **短所**: 実装・検証・説明のコストが高い。地上の正解データ（視程計など）での評価が前提。

**読み取れること**
- 期間全体を集約する方式（C〜F）は、**期間の長さで結果が大きく変わる**。C・F は長い期間で古い悪化を残し続け、D・E は冬期に悪化を薄める（D・E は冬期1日で視程不良を B の約1/4しか示さない）。
- 最新の通過に絞る方式（A・B・H）は、期間の長さに左右されにくい（B との一致率は期間によらず 98% 前後）。
- その中で B は、A・H より視程不良・注意を多めに示す（安全側）。差は通過内のばらつきの分だけなので小さい。

> 注: 正解データ（視程計・目視記録など）がないため、どの方式が「正しい」かは評価できません。上の比較は方式ごとの**傾向**を示すものです。

## 4. 採用方式 B の詳細

### 4.1 手順

```
入力: 表示期間 [start, end] 内に、区間へ紐付いた観測（seg_id, get_at, bus, wips, road_surface, image_path）
パラメータ: PASS_GAP_MINUTES = 10

1. 通過の分割
   区間・車両ごとに時刻順に並べ、前の観測との間隔が PASS_GAP_MINUTES を超えたら新しい通過とする。
2. 最新の通過の選択
   区間ごとに、通過の終了時刻が最も遅いものを選ぶ。
   同時刻に複数台が通過していた場合は、通過内の最小 WIPS が低い方（悪い方）を選ぶ。
3. 代表観測の選択
   選んだ通過の観測のうち、WIPS が最小の観測を代表点とする。同じ値なら新しい方。
   有効な WIPS が1つもなければ（全件が欠損・異常値）、通過内の最新観測を代表点とし、WIPS は「欠損」とする。
4. 出力
   代表観測の WIPS・路面状態・時刻・画像・車両に加え、参考として
   通過の開始/終了時刻・観測数、期間内の観測数・通過回数・WIPS 最小/中央値/最大を返す。
```

### 4.2 根拠

1. **鮮度（R1）**: 路面・視程は数十分単位で変化するため、最新の通過より前の観測は「現在」の推定に使わない。古い悪化を残し続ける C・F の問題（3章）を避けられる。
2. **安全側（R2）**: 1回の通過内のばらつきは、気象の変化ではなく、カメラの揺れ・対向車・遮蔽物などの短時間の撮影条件の差とみなせる。どれが真値か判断できない以上、注意喚起を目的とする本システムでは悪い側を採る。
3. **上流との一貫性（R5）**: WIPS 算出側も「10フレーム中の最小値」を採用し、その画像で路面状態を判別している。B は同じ考え方を「1回の通過」の単位に広げたもので、一言で説明できる。
   > 「その区間を最後に通過した車両の観測のうち、最も視界が悪かった瞬間」
4. **整合性（R3）**: 代表点は実在する1観測なので、表示される WIPS・路面状態・時刻・画像がすべて一致する。旧実装の「WIPS は平均、路面状態は最後の行」という不一致が解消し、利用者が画像で根拠を確認できる。
5. **計算コスト（R6）**: pandas の groupby と並べ替えだけで済む。直近24時間のキャッシュから代表点を選ぶ処理は約0.2秒で、スライダー操作ごとにサーバー側で再計算できる。

### 4.3 既知の限界

| 限界 | 影響 | 緩和策 |
|---|---|---|
| 通過内の単発の異常値を拾う | 1フレームの異常で「視程不良」になりうる | WIPS の有効範囲（`WIPS_VALID_MIN/MAX`）。車両単位の除外は行わない方針。将来は K（信頼度）を検討 |
| 最新の通過が1観測のみ | A（最新観測）と同じ挙動になる | 詳細パネルに期間内の統計と推移グラフを表示し、判断材料を補う |
| 通過の境界（10分） | 停車が長いと1回の通過が分かれる／短い間隔の別便が1回にまとまる | `PASS_GAP_MINUTES` で調整。路線バスの運行間隔に合わせる |
| 表示範囲の境界で通過が切れる | スライダーの端で通過の一部だけが使われる | 現状は仕様とする（範囲内の観測のみを使うことの方が説明しやすい） |
| 車両間の較正差 | 車両によって WIPS の尺度が違うと、どの車両が最後に通ったかで色が変わる | 車両ごとの分布の監視（レポート 5-1 参照）。将来は車両別の補正 |

### 4.4 パラメータ

| 名前 | 既定値 | 場所 | 意味 |
|---|---|---|---|
| `PASS_GAP_MINUTES` | 10 | `config.py` | 同一車両の観測をこの時間（分）以上空けば別の通過とする |
| `MATCH_DISTANCE_M` | 50 | `config.py` | 観測点を道路区間へ紐付ける最大距離 [m] |
| `WIPS_VALID_MIN` / `WIPS_VALID_MAX` | なし | 環境変数 | 範囲外の WIPS を欠損扱いにする |

## 5. 今後の検討事項

1. **正解データによる評価**: 道路気象テレメータの視程計や、CCTV の目視判定と突き合わせ、方式ごとの見逃し率・空振り率を測る。評価できれば B・H・G などの比較に根拠を与えられる。
2. **方式の切替**: `services/representative.py` の `select_representatives` は差し替えやすい構成にしてある。比較用に複数方式を実装し、設定で切り替えられるようにする案がある。
3. **路面状態の独立判定（J）**: 路面状態は WIPS と相関しない場面（晴天の凍結路など）がある。路面状態だけは「最新通過内で最も滑りやすい区分」を採る方式も、安全側として検討の余地がある（ただし R3 の整合性は失われる）。
4. **信頼度・状態推定（K・L）**: 車両ごとの較正、夜間・逆光の判定、観測のない時間の不確かさの表現。本番化の段階で検討する。
